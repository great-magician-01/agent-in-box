# Agent-in-Box 完整产品方案

> 文档状态：总体方案草案 v0.1  
> 本文汇总当前讨论形成的产品决策。技术选型和验证事项见《技术设计文档》，实施顺序见《开发计划》。

## 1. 产品定位

Agent-in-Box 是一个面向个人用户的本地 AI 虚拟机工作平台。用户通过 Electron、本地网页、飞书或 QQ 与主会话 Router 对话，由 Router 将工作分派给完整的 Worker Agent，Worker 在用户电脑上的 Linux 或 Windows 虚拟机中执行任务。

本期采用 **Linux 全链路先行、Windows VM 随后完成** 的开发顺序：**Windows 宿主机运行 Linux VM 是必须支持的 P0 基础能力**；先完成 Linux VM 从镜像到 AI 执行、任务恢复和多端接入的完整验证，再开始 Windows VM 的可行性验证与对应开发。Windows 镜像下载可以提前进行。Windows VM 属于本期最终交付范围，不是可选功能，也不移到下一期。

产品的核心不是单次聊天，也不是一次性远程桌面，而是：

- 用户拥有多个长期项目区；
- 每个项目区可以有多个会话和多个任务；
- Router 知道任务曾经分配给哪个 Worker；
- Worker 是具有独立上下文、工具、会话历史和生命周期的完整 Agent；
- AI 通过 Computer Use 操作虚拟机中的桌面、应用和项目文件；
- 虚拟机、Worker、会话和任务均可长期保存、停止、恢复和归档；
- 用户始终可以查看、审批、接管和停止 AI 的操作。

## 2. 核心产品原则

### 2.1 本地优先，云端增强

- VM 默认运行在用户自己的电脑上。
- 用户不需要购买或维护服务器。
- 本地核心功能不依赖产品方控制服务器。
- 云端可用于模型 API、镜像下载源以及未来可选的远程访问增强。
- 飞书和 QQ 默认由本地客户端通过官方长连接直接接入，不经过产品方机器人中继。

### 2.2 AI 原生 Computer Use

- AI 的主要操作方式是观察屏幕并执行鼠标、键盘和滚动等桌面动作。
- 可以辅以文件、Shell、OCR、可访问性树和浏览器状态等工具，但不能把 GUI 操作降级为单纯聊天或固定脚本。
- 每次关键动作后重新观察环境，验证动作结果，而不是盲目连续执行。
- 长任务需要支持暂停、取消、超时、卡住检测、人工接管和结果验证。

### 2.3 直接执行局限于 VM

- Router 和平台控制服务不获得 AI 生成的宿主机 Shell 能力。
- Worker 默认在目标 VM 内运行，文件和 Shell 工具天然作用于 VM。
- VM 管理接口由确定性的系统服务控制，不向模型开放任意 Hypervisor 指令。
- 宿主机 API Key、机器人凭据和本地数据库不进入 VM。
- 通过 VM 网络访问外部系统仍可能产生外部影响，因此还需要网络策略和人工审批。

### 2.4 不限制 VM 的拥有数量，只调度运行资源

- 不限制用户下载多少个镜像。
- 不限制用户创建、保留多少台 VM。
- 用户可以下载后停止不用，停止的 VM 保留磁盘和项目绑定。
- 普通个人电脑通常只适合同时运行少量 VM，但这不是产品的固定数量限制。
- 资源不足时，自动任务排队并提示用户；不能擅自关闭其他正在执行任务的 VM。
- 用户可以手动启动更多 VM，产品提供资源提示和软预算，而不是硬性禁止。

### 2.5 项目与 VM 多对多绑定

同时支持：

1. 多个项目共享一台 VM，适合普通个人电脑；
2. 一个项目独占一台 VM，适合需要独立环境的项目；
3. 一个项目绑定 Linux 和 Windows 两台 VM，处理跨平台工作。

项目与 VM 不再是一对一关系。项目区是逻辑工作区，VM 是可停止、可替换、可复用的执行环境。

### 2.6 同一份事实，多种展示

- 数据库和持久事件是任务状态的唯一事实来源。
- 用户任务看板和 Router 读取的是同一份数据的不同投影。
- Worker 分配关系不能只存在于模型上下文中。
- Router 重启、压缩上下文或更换模型后，仍能恢复正确的任务和 Worker 关系。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| Image | 可复用的虚拟机基础镜像，可下载、校验、缓存和版本化 |
| VMInstance | 用户创建的一台虚拟机实例，拥有独立磁盘、配置、状态和绑定项目 |
| Project | 逻辑项目区，保存项目说明、会话、任务、工作区、产物和项目记忆 |
| ProjectVmBinding | 项目与 VM 的绑定关系，可指定主环境和工作目录 |
| Conversation | 用户可见的持续会话，包括主 Router 会话和项目/Worker 会话 |
| Router | 主会话 Agent，负责理解需求、协调项目、复用或创建 Worker、汇总结果 |
| Worker | 绑定 Project + VM 的完整 Agent，具有独立上下文、工具和执行生命周期 |
| Task / Run | 一次可分派、排队、执行、暂停、审批、完成或失败的工作记录 |
| Guest Agent | VM 内的受控系统组件，提供截图、输入、健康检查和文件交换能力 |
| Task Board | 面向用户的可视化任务区，同时为 Router 提供结构化读模型 |
| Worker Registry | 持久记录 Worker、会话绑定、当前任务、活跃状态和归档位置 |

## 5. 虚拟机管理方案

### 5.1 自动获取镜像

用户创建 VM 时选择操作系统和模板，本地服务自动完成：

1. 检查镜像缓存；
2. 从配置的官方或产品镜像源下载；
3. 显示下载进度并支持断点续传；
4. 校验哈希和签名；
5. 创建 VM 磁盘与配置；
6. 初始化 Guest Agent、Worker、桌面和基础应用；
7. 启动并执行健康检查；
8. 健康检查通过后进入可用状态。

Linux 优先使用官方 Cloud Image 或经过测试的产品 Golden Image。Windows 支持合法 ISO、评估镜像或企业内部镜像，并通过无人值守安装和镜像构建流程生成可用环境。Windows 授权、激活和镜像分发需单独处理，不能默认提供无许可的商用 Windows 镜像。

本期允许提前实现 Windows 镜像的下载、续传、校验和存储，但这只属于 Image Service 能力，不代表 Windows VM 已具备可行性。Windows VM 的创建、启动、Guest Agent、Computer Use 和任务验证必须等待 Linux 全链路验收后开展，并在本期后段完成。

### 5.2 镜像和 VM 分开管理

- 镜像可下载但不创建 VM；
- VM 可创建后长期停止；
- 多 VM 可共享同一个只读基础镜像，但拥有各自可写磁盘；
- 正在使用的镜像版本不随后台更新自动变化；
- 删除镜像缓存前检查 VM 依赖；
- 清理缓存和删除用户 VM 必须是不同操作。

### 5.3 VM 状态

```text
Stopped → Starting → Running → Stopping → Stopped
                   │
                   └→ Suspended / Saved
Running / Starting / Stopping → Error
```

- Stopped：保留磁盘、项目和 Worker 绑定，基本不占运行内存；
- Suspended/Saved：保存现场并释放运行内存，但占用额外磁盘；
- Running：实际使用 CPU、内存和显示资源；
- Error：保留诊断信息，不自动假设任务可以继续。

### 5.4 自定义存储位置

必须区分应用本体和大体积 VM 数据。即使应用本体位于系统盘，以下数据也能放到用户选择的位置：

- 镜像缓存；
- 未完成下载；
- VM 虚拟磁盘；
- VM 快照和休眠现场；
- 可选的大型归档与任务产物。

支持首次启动选择、按 VM 覆盖以及后续迁移。迁移时先停止相关 VM，复制并校验，原子切换路径，验证成功后由用户确认是否清理旧副本。不能只改配置路径而忽略 QCOW2 backing file 和快照链。

### 5.5 本机资源调度

资源管理器采用动态资源预算，而不是固定 VM 数量：

- 为宿主机保留可配置的资源余量；
- 统计当前运行 VM 的分配和实际压力；
- 启动前检查内存和磁盘；
- 自动任务资源不足时进入 `waiting_resources`；
- 提示用户停止、休眠其他 VM 或调整资源配置；
- 不擅自中断已有任务；
- 手动模式允许用户自行决定启动哪些 VM。

### 5.6 共享 VM 的影响

同一 VM 中的项目默认共享操作系统、软件、网络和桌面状态。项目可以拥有独立目录、会话、Worker 和产物，但不能因此宣称项目之间具有强安全隔离。

共享 VM 还意味着：

- 一个项目安装软件可能影响其他项目；
- 一个项目修改系统配置可能影响其他项目；
- 恢复整台 VM 快照会回滚所有绑定项目；
- 项目级回滚应使用 Git、文件备份、项目目录快照和产物版本；
- 删除项目不能删除仍被其他项目使用的 VM。

如需要更强隔离，用户可选择项目独占 VM。VM 内 OS 用户、ACL 或容器可以作为增强措施，但不能等同于独立 VM，尤其当多个 Worker 共享一个桌面会话时。

## 6. 项目、会话与执行模型

### 6.1 项目区

项目区保存：

- 项目说明和长期目标；
- VM 绑定及默认环境；
- 项目工作目录；
- 用户会话和 Worker 会话；
- 任务、文件和产物；
- 项目级记忆和重要决策；
- 权限、网络和凭据策略；
- 项目活动记录。

项目可以绑定已停止的 VM，不需要为了配置项目而一直运行 VM。

### 6.2 多会话共享环境

一个项目可以有多个会话。会话历史独立，但绑定同一 VM 时环境共享：

- 会话 A 修改的文件可被会话 B 读取；
- 会话 A 安装的软件可能影响会话 B；
- 会话 A 打开的桌面和应用可能被会话 B 看到；
- 用户界面必须明确显示“这些会话共享执行环境”。

### 6.3 执行并发

- 不同运行中的 VM 可以并行执行任务；
- 同一 VM 默认同时只有一个执行 Worker；
- 同一 VM 上不同项目的任务进入同一个执行队列；
- 对话、规划和查看历史不占 VM 执行锁；
- 新建 Worker 不代表可以绕过 VM 队列；
- 人工接管获得独占控制权，AI 暂停桌面操作；
- 后续可探索只读任务并行，首版不开放同 VM 多 Worker 写入并行。

## 7. Router–Worker 方案

### 7.1 Router 的职责

Router 是主会话中的完整 Agent，类似用户面对的项目协调者。它负责：

- 理解目标并必要时澄清；
- 识别目标项目和目标操作系统；
- 查询已有 Worker 和任务；
- 决定复用、恢复或新建 Worker；
- 创建任务、设置依赖和优先级；
- 汇总多个项目的进度和结果；
- 向用户转发审批、错误和完成通知；
- 响应暂停、取消、重试等控制请求。

Router 不直接拥有鼠标、键盘、VM Shell 或任意 Hypervisor 工具。Router 提出调度意图，本地控制服务负责鉴权、校验和实际分派。

Router 是逻辑角色，不是所有会话共用一个不可扩展的全局 Agent 进程。每个主会话可以拥有独立 Router 上下文，底层共享持久任务系统。

### 7.2 Worker 是完整 Agent

Worker 具有：

- 独立 System Prompt 和模型上下文；
- 独立持久会话；
- 完整工具调用循环；
- 工具集合和能力标签；
- 压缩、恢复、取消和心跳机制；
- 任务结果和完整审计轨迹；
- 与 Project + VM 的稳定绑定。

Worker 不是 Router 的一次性子代理调用。Router 返回用户消息后，Worker 仍可继续执行；用户也可以进入 Worker 对应的项目会话直接交流。

### 7.3 会话绑定

持久记录：

- 用户来源会话；
- 项目；
- Worker；
- Worker 内部 Agent Session；
- 最近任务；
- 绑定创建时间和状态。

因此“继续刚才那个任务”“让之前做报表的 Worker 再处理一份数据”等请求可以在 Router 重启后正确解析。

### 7.4 复用还是新建 Worker

| 场景 | 默认决策 |
| --- | --- |
| 对正在执行任务的纠正 | 复用 Worker，发送 Steer |
| 当前任务完成后的连续工作 | 复用原 Worker |
| 新任务依赖原任务上下文 | 复用原 Worker |
| 同项目但独立的新目标 | 可新建 Worker |
| 需要不同能力或不同 VM | 新建对应 Worker |
| 不同项目 | 不跨项目复用 Worker |
| 已归档但用户明确要求继续 | 恢复原 Worker或基于归档重建 |
| 原上下文过长、混乱或版本不兼容 | 新建 Worker并携带摘要 |

Worker 复用和 VM 调度是两个独立决策。复用或新建之后，任务仍须获得目标 VM 的执行权。

### 7.5 运行中消息的类型

- Steer：影响当前工作，例如纠正路径或要求停止某类操作；
- Follow-up：当前工作完成后继续执行；
- New Task：创建独立任务并进入目标 VM 队列；
- Abort：取消当前执行并进入可审计的取消状态。

### 7.6 Worker 自动归档

生命周期：

```text
Running → Idle → Archiving → Archived
Archived → Restoring → Idle
```

只有满足以下条件才自动归档：

- 没有运行中的任务；
- 没有排队消息；
- 没有等待审批；
- 不持有 VM 执行锁；
- 会话、任务结果和产物引用已持久化。

归档保存 Worker 元数据、会话位置、恢复检查点、任务摘要、最近结果、产物引用、Project + VM 绑定、引擎与模型版本、最后活跃时间。

归档后：

- 从 Router 活跃 Worker 工作集移除；
- 从任务看板默认活跃视图移除；
- 保留在可搜索的归档区；
- 不删除任务历史、项目文件或产物；
- 不等于停止 VM；
- 不等于删除 Worker。

恢复时必须补充当前最新截图、VM 当前状态以及 Worker 离开期间的环境和其他任务变化，防止其沿用已经过期的桌面或文件认知。原生会话不可恢复时，采用新 Worker 加载归档摘要的语义恢复，不承诺跨版本无损恢复。

## 8. 可视化任务看板

### 8.1 看板状态

- Backlog / 待排队；
- Waiting Resources / 等待本机资源；
- Waiting VM / 等待 VM 启动；
- Queued / 等待 VM 执行权；
- Running / 执行中；
- Waiting Approval / 等待审批；
- Blocked / 已阻塞；
- Completed / 已完成；
- Failed / 失败；
- Cancelled / 已取消；
- Archived History / 归档历史。

### 8.2 任务卡片

每张卡片至少展示：标题、目标摘要、项目、目标 VM、Worker、来源会话、状态、最新进度、优先级、依赖、创建时间、耗时、产物、失败原因和待处理审批。

### 8.3 用户操作

- 调整排队任务优先级；
- 暂停、继续、取消和重试；
- 处理审批；
- 打开 Worker 会话；
- 查看 VM 实时画面和人工接管；
- 查看执行时间线、关键截图和产物；
- 按项目、VM、Worker 和状态筛选；
- 查看、恢复或搜索已归档 Worker。

拖拽主要用于调整优先级，不允许仅通过把任务拖到“完成”就伪造执行成功。所有状态变化由任务状态机和明确操作产生。

### 8.4 Router 读取

Router 默认读取活跃 Worker 卡片、未完成任务、等待用户处理事项和最近结果摘要。完整对话、全部截图和每步操作只在用户或 Router 主动查询任务详情时加载。

归档不是删除 Router 的历史消息，而是让后续活跃工作集快照不再包含该 Worker；历史记录仍保存在数据库中。

## 9. Computer Use 与人工控制

Worker 的基本闭环：

```text
接收任务 → 获取截图和环境状态 → 模型决策 → 校验动作
→ 在目标 VM 执行 → 获取新截图 → 验证结果 → 继续或结束
```

基础工具包括截图、点击、双击、移动、输入、按键、滚动、拖拽和等待。可按需增加文件、Shell、OCR、窗口状态和浏览器信息工具。

必须支持：

- 屏幕分辨率和 DPI 适配；
- 中文及 Unicode 输入；
- 动作序号、截图序号和审计记录；
- 最大步数、时长和任务超时；
- 重复动作、无进展和卡死检测；
- 取消和断线后的状态核对；
- 完成前的结果验证；
- 人工接管与 AI 控制权互斥。

Windows 安全桌面、UAC 等系统边界在本期后段 Windows VM 开发中单独验证，不保证可自动操作，不能通过绕过系统安全机制实现；必要时请用户人工处理。

## 10. Web、Electron、飞书和 QQ

### 10.1 Web 与 Electron

- Web 和 Electron 复用同一套前端。
- 本地网页由本地控制服务提供，可在浏览器访问本机实例。
- Electron 负责桌面安装、后台服务管理、本地通知、文件拖放和自动更新等能力。
- Electron 渲染进程不直接持有 Hypervisor 或管理员权限。
- 远程网页访问可作为后续可选云端中继功能，不是本地核心使用的前提。

### 10.2 本地机器人直连

本地 Connector 通过官方 WebSocket 长连接接收事件，通过 HTTPS API 回复消息。用户不需要公网 IP、Webhook 域名、端口映射或自备服务器。

飞书需要完成开放平台应用、机器人能力、权限和事件配置；QQ 需要满足对应机器人类型的开发者注册、权限和 Intents 配置。无服务器不代表免除平台审核和配置。

Connector 运行在本地后台服务中，负责：

- 连接、心跳和断线重连；
- 事件去重和本地持久化；
- 消息快速接收、任务异步执行；
- 平台用户与本地用户绑定；
- 用户和群聊白名单；
- 任务进度、审批和结果通知；
- 机器人与当前电脑的绑定。

首版默认一个机器人只绑定一台活跃执行电脑，避免同一消息被多台电脑中的随机一个实例处理。

### 10.3 离线限制

电脑关机、休眠、断网或后台服务退出时：

- 本地 VM 和 Worker 无法继续工作；
- 本地机器人无法实时接收和回复；
- 离线消息是否补投取决于平台机制；
- 无云端队列时不能承诺离线消息绝不丢失；
- 重新上线后必须核对任务和 Worker 实际状态，不能盲目继续旧动作。

## 11. 安全与隐私

- VM 是宿主机与 AI 执行环境之间的主要安全边界；
- 同 VM 的项目默认只有逻辑隔离；
- 默认不共享宿主机目录、设备或宿主机剪贴板；
- 文件交换通过受控的文件传输功能；
- VM 默认无入站连接，限制宿主机管理网段、内网敏感地址和云元数据地址；
- 按任务或项目配置出网策略；
- 模型、飞书和 QQ 的长期凭据保存在宿主机 OS 安全凭据存储中；
- VM 只获得短期、限范围的管理或模型访问凭据；
- 机器人消息和网页内容都是不可信输入，不能自动提升为系统指令；
- 登录、付款、发布、发送、删除、对外上传等动作可配置人工审批；
- 审计记录保存工具动作、结果、关键截图和审批，不依赖模型自述完成；
- 日志和截图可能包含敏感信息，需要提供本地保护、保留期限和清理机制。

## 12. 本期范围与开发顺序

### 12.1 P0 基础能力：Windows 宿主机运行 Linux VM

这是必须支持的首要运行形态，不是可选保留能力。需要完成 Windows 宿主机检测、Hypervisor 适配、本地安装、自定义存储、Linux 镜像下载、Linux VM 启停、Guest Agent、控制台和故障恢复。

### 12.2 Linux 全链路先行里程碑

在 Windows VM 的可行性验证和对应开发开始之前，先完整验证：

- Linux 镜像自动下载、校验和 Golden Image；
- Linux VM 创建、启动、停止、休眠和恢复；
- Linux Guest Agent、屏幕查看、Computer Use 和人工接管；
- Pi Worker 或经验证的替代 Worker Engine；
- 项目、会话、任务、VM 多对多绑定；
- Per-VM 串行调度和本机资源管理；
- Router、Worker 注册表、复用决策、归档和恢复；
- 任务看板；
- 飞书和 QQ 本地长连接；
- 本地审计、权限、审批、故障恢复和真实任务集。

只有上述 Linux 链路完整验收后，才进入 Windows VM 的可行性和功能开发阶段。

### 12.3 Windows VM：本期后段交付

Windows VM 不移出本期。其镜像下载、校验和存储可以提前复用 Image Service 完成，但提前下载不代表 Windows VM 已验证或可支持。

Linux 全链路验收后，本期继续完成：

- Windows 合法镜像来源、无人值守安装和 Golden Image 构建验证；
- VirtIO、显示、DPI、桌面会话、输入和授权处理；
- Windows Guest Agent 和 Pi Worker；
- Windows Computer Use、取消、恢复、审批和人工接管；
- Linux/Windows 混合 VM 绑定、调度和资源测试；
- Windows 真实任务集及 Linux 全量回归。

### 12.4 不作为本期前提

- 同 VM 多 Worker 同时写入执行；
- 企业级多租户和云端 VM 集群；
- 所有平台、所有机器人类型的无条件兼容；
- 所有长任务完全无人监督且百分之百成功；
- 跨 Worker Engine 和跨版本的无损会话恢复；
- 低延迟 WebRTC 远程桌面；
- 云端离线任务队列和远程 Web 中继。

后续增加云端 VM 时，应通过新的 VmProvider 实现，不重写项目、Router、Worker 和任务系统。

## 13. 本期完整版本的产品级验收场景

以下清单包含 Linux 先行里程碑和本期后段 Windows VM 的最终联合验收，不能把仅通过 Linux 里程碑当作本期全部完成。

1. 用户在一台没有 VM 的电脑上安装应用，选择非系统盘目录，自动下载镜像并启动 VM。
2. 下载中断和应用重启后能够续传，校验失败文件不会被当作有效镜像。
3. 用户创建多台 VM 并停止其中大部分，项目绑定和 Worker 历史保持完整。
4. 多个项目共享 Linux VM，同一时刻只有一个 Worker 执行，其他任务明确排队。
5. Linux 和 Windows VM 在资源允许时并行执行不同项目任务。
6. 资源不足时新任务等待，系统不擅自停止已有 VM。
7. Router 重启后仍知道每个任务分配给哪个 Worker，以及每个 Worker 的来源会话。
8. Router 能复用相关 Worker，也能为独立目标创建新 Worker。
9. 空闲 Worker 自动归档并退出 Router 活跃工作集，之后可以搜索和恢复。
10. 恢复 Worker 时会获得离开期间的 VM 和项目变化，不使用过期截图直接操作。
11. 用户任务看板与 Router 查询结果一致，任务完成具有真实结果和产物记录。
12. 用户可以随时接管 VM，接管期间 AI 不再注入桌面输入。
13. 飞书和 QQ 在无公网 IP、无用户服务器的情况下通过本地长连接收发任务。
14. 机器人离线时界面明确显示离线，恢复连接后不重复执行已处理消息。
15. VM 中执行的文件和 Shell 操作不能默认访问宿主机文件、凭据和管理接口。
