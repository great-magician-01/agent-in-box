Interpretation: paths with ASCII spaces work; paths containing Chinese
characters fail for every QEMU file consumer tested (-pidfile, -serial, -drive).
qemu-img itself handles the Unicode path. The Windows ANSI code page is CP936,
so QEMU's UTF-8 path handling is not sufficient for ANSI file APIs. This is a
QEMU-on-Windows file path limitation, not a space-only or drive-letter issue.
No system setting was changed to test the UTF-8 beta locale workaround.
